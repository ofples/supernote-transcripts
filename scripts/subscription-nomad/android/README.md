# Supernote Bridge

Supernote Bridge is an optional Android companion for transcript page links, the older direct-browser OAuth loopback callback, and Obsidian Digest capture. Ordinary Markdown reading, AI recognition, and desktop-assisted account pairing work without it. Digest entries can retain a notebook/page as reference provenance; this build does not create embedded `.note` Digest links or claim native Digest page-jump support. Supernote Bridge is not the retired `nomad-subscription-test` Obsidian plugin; do not install that test plugin.

Bridge opens from Obsidian's page-link or Digest action. It does not add a separate launcher icon; its installed name is visible in Android's app settings.

## Build and install from source

Build the local debug APK with an Android development environment; skip this step if you only want transcripts for now.

1. Install JDK 17, Gradle 8.13 and Android SDK platform 35 with its build tools. Configure `ANDROID_HOME` for your SDK, or create an ignored `local.properties` with `sdk.dir` pointing to it. This folder does not include a Gradle wrapper.
2. From this directory, run:

   ```sh
   gradle assembleDebug
   ```

3. Find the generated debug APK under `build/outputs/apk/debug/`. With the Nomad's sideloading enabled and a working Android platform-tools connection, install that APK using `adb install -r <path-to-apk>`; substitute the actual generated filename. Approve any device prompt. USB is needed only for this installation method, not ordinary page navigation.
4. Open a managed transcript in Obsidian Reading view, enable notebook page links in Transcripts, and tap **p.N ↗**. The corresponding source must also be configured locally on Nomad. See [page navigation](../../../PAGE_LINKS.md) and the [full workflow](../../../docs/workflow.md).

Android upgrades must use the same signing key as the existing helper. Keep your signing key private and backed up. A signature mismatch is an installation failure, not a reason to erase application state. The native Notes handoff was tested on the firmware recorded in the page-navigation document; compatibility with every firmware version is not guaranteed.

The next Bridge candidate declares versionName `0.6.1` and increments versionCode to 9. `assembleDebug` produces a debug-signed candidate; confirm its certificate matches the established Bridge signer before treating it as an in-place upgrade or release artifact.

## Current architecture and integration details

The app keeps the application ID `tools.supernote.logincallback`, existing login and Note routes, and signing identity so upgrades preserve the installed app and its state. The exported `LoginActivity` validates an older direct-browser authorization link and starts `CallbackService`, which accepts the OAuth return on loopback; desktop-assisted account pairing does not use this helper. The exported `OpenNoteActivity` validates transcript links and opens the native Note editor.

The exported `DigestActivity` accepts bounded v1 requests at `supernote-bridge://digest` as a transparent, no-history handoff. A signed Quick Digest request is validated against the device-local trust record, timestamp, vault, payload hash, and replay ledger. The optional signed `delivery` JSON carries `openNative` and an optional exact native category name; it does not change the payload hash or request ID. **Quick Digest** (`openNative: false`) saves once, verifies the provider acknowledgement and saved row, records a local SAVED receipt, then calls Reader while leaving Reader in front. **Create Digest** (`openNative: true`) performs that same verified save and opens the saved row in native Digest details, where the user can tap **Edit**. Native details are read-only initially. Trusted requests do not show a Bridge page or prompt.

On first use for a Reader client, Bridge shows one standard Android **Allow Obsidian to create Digests?** permission dialog. Bridge verifies the signed setup request before showing it, and stores its secret only after the user allows. Later signed requests from that client need no Bridge interaction. An unsigned legacy review request never creates a Digest; it opens the native Knowledge app and asks the user to reconnect Reader. The `supernote-bridge://digest-settings` route opens the native Knowledge app. An explicit empty category name selects native **Uncategorized**. A nonempty category name must exactly match one current native category; missing or ambiguous names fail before the provider write and return a bounded cancellation reason to Reader. If category is omitted, Bridge uses its saved device-local default and falls back to **Uncategorized** if unavailable.

The `supernote-bridge://digest-receipt?request=<64-lowercase-hex>` route opens a saved entry from Reader's **Open Digest** action on an associated Reader Highlight. Bridge resolves the row ID from its device-local ledger and accepts the route only for a local `SAVED` receipt. The optional `&id=<positive-decimal>` remains supported and must exactly match the saved ID. Unknown requests, non-saved receipts, and mismatched IDs are rejected before launch. Bridge does not check whether the native row still exists; the native app handles a deleted or unavailable entry after a valid launch. The Reader Highlight is a regular Markdown record that Obsidian Sync can carry, but the receipt is device-local; a synced highlight on another device may not have a receipt that can authorize opening the Digest. Removing the highlight does not delete the native Digest. Bridge validates the known Knowledge provider and exported native detail activity, then launches that exact activity with only `knowledge_id` and `from_app=knowledge`. It does not query, create, update, or delete a provider row on this route. The native entry opens in read-only details and provides its own **Edit** control.

Reader signs requests with a per-vault secret kept in device-local Reader `localStorage`; that secret is not part of synced Obsidian plugin settings. Bridge keeps its copy in Android Keystore-encrypted app preferences. Neither copy is written to logs. The exact original payload JSON remains the identity input for request hash and deduplication; delivery options have a separate HMAC binding. A saved request is verified from its local receipt and never reinserted or moved if a later delivery names a different category. The ledger stores request ID, payload hash, status, returned row ID, selected comment, and list association, but never the selected quote text. Existing ledger entries are upgraded in place; legacy receipts retain their original comment verification and skip list-association checks because older ledger rows did not record the selected list. A pre-v2 SAVED receipt without a stored comment uses the exact original comment formatter for readback; new receipts verify their stored comment byte-for-byte.

Every write requires the exact Supernote Knowledge provider component, package and read/write permissions; the provider list query and writes use fixed URIs with no caller-supplied SQL. The Bridge writes at most once per request ID and verifies the returned row ID and expected row fields before recording SAVED. It permits only the provider-generated root `unique_identifier` as an extra metadata field. Uncertain writes are not retried. Reader Highlights are persisted before handoff and remain standalone when a save is cancelled or uncertain. `openNative: true` keeps native Digests in front after the detail screen opens; `false` returns a verified SAVED callback to Reader. Authenticated no-write failures return `cancelled`, ambiguous writes return `uncertain`, and verified saves return `saved` with their ID when Reader requests a callback. Category failures may include only the bounded reasons `category-not-found` or `category-ambiguous`. Reader's **Open Digest** action relies on Bridge's local `SAVED` receipt instead of a success foreground callback.

Every saved Digest comment includes a readable notebook name. For a Supernote source it also includes the known one-based page; for an ordinary Markdown source it includes the available heading instead, without inventing a page. The user note remains first, followed by notebook/page provenance and the Obsidian source link. The 2,000-character provider limit includes this provenance.

Notebook/page data remains provenance in the comment and `supernote_bridge.note` metadata. Knowledge 1.00.153 static APK inspection shows the native Digest source action requires an embedded `.note` textbox reference keyed by provider `unique_identifier`; an ordinary comment URL is not clickable. Bridge and Reader do not modify original `.note` files, so native Digest-to-notebook page jumping is unavailable. This APK inspection is not a live UI verification. Live ADB checks on the active local candidates confirmed Quick Digest silent save and Reader return, same-quote duplicate protection, Create Digest opening the matching synthetic excerpt in native details, missing-category cancellation before provider insert, a corrected same-request retry to SAVED without a second Highlight, and an exact **Uncategorized** name saving silently to Reader. The saved Highlight reappeared after reopening. Cleanup removed the three test Digests through individual native Details confirmations, the fixture source/folder and three owned Highlight files, and local test requests. Three Bridge audit receipts were intentionally retained; ten earlier ledger rows and trust/preferences were unchanged. The original reading location, five Reader leaves, and exact 20-position map were restored; the global category is blank. The recognition queue is idle and durably paused, automatic checks are off, and no recognition ran. A nondefault native category and two-device category sync were not live-tested; automatic menu opening after a long hardware drag was not retested.

Obsidian can request a note page with:

```text
supernote-transcripts://open-note?file=<percent-encoded-absolute-path>&page=<positive-1-based-page>
```

`OpenNoteActivity` accepts only `ACTION_VIEW` links with that exact scheme and authority, one `file` and one `page` query value, and a positive decimal page. It requires a case-insensitive `.note` path whose canonical location stays below `/storage/emulated/0/Note`, rejects dot segments, controls, backslashes, and encoded separator remnants, then sends only `file_path` and the 1-based `page` to the explicit Supernote Note editor activity. It does not request storage access or read or modify note content. It does not relay arbitrary intents or invoke a shell. Errors stay on the helper screen and contain no path or query data.

The target component and extras match the existing SuperTask `NoteOpenerModule` implementation. Preserve the signing key when upgrading an installed helper.
